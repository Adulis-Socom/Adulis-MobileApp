# Adversarial reviews

**A review lands here as a committed artifact** (T8-R S3). One file per phase,
written BEFORE the fixes it prompts, and every register entry it produces cites
it by path.

**A review names the ref it ran against.** The T8 Phase 4 reviewer watched an
untracked probe file appear and vanish mid-pass, and fifty-three uncommitted
lines arrive in a suite it was reading. A review whose baseline moves
underneath it is a review of nothing in particular; naming the ref makes that
visible instead of silent.

## Why most of this directory is stubs

Every review before T8-R ran in a session and was never committed. The register
cites their findings by number; the evidence -- the measured tables, the
enumeration cells, the byte offsets, the count a broken gate printed as a pass
-- lived only in those sessions.

That is D-56's complaint arriving from the other direction. **D-56 is a
citation pointing at no entry; this was an entry pointing at no evidence.**

Four are recovered in full, from run artifacts that happened to survive on
disk. The rest are stubs: what the review found, which commit applied it, and
which register entries it produced. **The stubs do not reconstruct the
reviewers' reasoning.** Where the evidence is lost, they say so. A fabricated
review is worse than a missing one, because the next reader cannot tell.
