# RBL-04 -- Architecture decision record, ownership map and product contract register

Status: ADR for the replacement lineage (RB25-D01). Governs Stage B onward. It defines OWNERSHIP and
CONTRACT BOUNDARIES only: **no production business endpoint exists before its assigned frontend/backend
stage**, and a missing contract is a GAP, never a licence to invent one.

## ADR-RB-01 Decision
One backend (NestJS on Fastify) as a modular monolith with two processes from one codebase (API and worker),
over one PostgreSQL (clean Drizzle lineage, RLS and invariants in SQL) and Valkey (BullMQ queues and a
separate rebuildable cache, per DEPLOY-01), with a PostgreSQL transactional outbox as the only source of
cross-domain events. Four clients reach it only through the generated OpenAPI client. No BFF, no
microservice, no app-to-app import, no legacy runtime. Sources: ARCH-PLATFORM-01, DEPLOY-01, EVT-01,
AUTH-02, CSP-01; decisions D24-08..10, RB25-D01.

Consequences: every table and event has exactly one owner module; other modules read through the owner's
application service or a projection fed by its events; clients never compute authoritative state.

## 2. Allowed dependency graph
```
apps/console  --+
apps/mobile   --+--> packages/api-client (generated) --> HTTP --> apps/api (API process)
apps/storefront-+--> packages/tokens, packages/locale, packages/config
apps/operator --+
apps/api (worker process) <-- same codebase, separate entry point
packages/* --> packages/* (acyclic); packages/* never import apps/*; apps/* never import apps/*
fixture port (dev only, per client) --X--> never imported by a release build; never reaches the network
```
Enforced by dependency-cruiser (rules carried, REUSE VERIFIED) and the release-negative gate (GOV-06).

## 3. Auth audiences (AUTH-02 S32-S33)
| Audience | Principal | Surface | Notes |
|---|---|---|---|
| CONSOLE | ordinary Account (Seller relationship) | Seller Console | opaque stateful session, cookie, CSRF, step-up |
| MOBILE | ordinary Account (Buyer / Seller Companion / Courier relationships) | Mobile | mode switch never re-authenticates; backend asserts available modes |
| OPERATOR | Operator Account (CEO, COO/CTO only; Staff model behind a disabled flag; CMO none) | Operator | WebAuthn; cannot be manufactured from an ordinary session |
| (anonymous public) | none | Storefront, public discovery | every read resolves current public eligibility |
Audiences never cross; surface derives from the validated session and route, never from a request field.
